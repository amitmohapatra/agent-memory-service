# Handoff: precise context and clean memory (2026-11-28)

For the next agent picking this up. What changed, why, what is verified, and what is left.
Read with `CHANGELOG.md` (Unreleased) and ADRs 0048-0051.

## Goal the owner set

- The context an agent gets is **precise**: only what bears on the question, each statement
  once, the same sections in the same order every time, everything dated.
- **The agent fetches the rest on demand** (memory tools), like Claude Code / Letta.
- **No hardcoded language rules** deciding what a person said: where a model is allowed it
  reads; what the app or the source says (role, origin, kind) decides the rest.
- Memory is the single durable source of truth, multi-tenant, high throughput.

## What changed (all on main)

| Change | Why |
|---|---|
| Context check (ADR 0048): one fast-model call removes what does not help the question | similarity alone attached noise (1% of a hand-counted context was used) |
| Test set for the check (`benchmark/context_check.py`) | to measure the check with a real model |
| "Last / first message" read by time (`memory_search` `order`, `said_by`, `here`) | a search by meaning returned the wrong message |
| Graph facts searchable (`kinds: ["fact"]`) | facts were reachable only through the context |
| End dates (ADR 0049): "for today only ..." expires on its last day | time-limited instructions were kept forever or not at all |
| Clean-up tool (ADR 0050, `tools/clean_up.py`, dry run by default) | memory stored before a model read messages holds pasted text as the person's rules |
| On-demand context (ADR 0051, `recall: false`; SDK 0.6.9) | an agent that searches itself needs only what stands |
| "this conversation" on rules/preferences said here | a model could not tell a rule given here from one given weeks ago |
| Learned skills carry their task match (SDK 0.6.10) | a skill for the wrong task looked like one for this task |
| `origin` on messages: person / app / schedule (SDK 0.6.11) | UI-service, WebMCP and schedule text became the person's preferences |
| Profile `user` block = identity only; rules/preferences come where they apply; each statement once (`demand.said_once`) | the same line reached the prompt 2-3 times; unrelated rules went with every request |
| Facts that repeat a shown memory and graph bookkeeping ("u1 mentions X") not shown; plain "said" turns not grouped as a slot | duplicates and layout noise |
| `profile_edit` refuses to replace a block that holds text unless the old text is passed | an agent could overwrite lines it never read |
| Events / files never become the person's rule, preference or profile | an event saying "never call after 6pm" became the user's rule |
| Hindsight extraction preview removed | ran on a model of its own, used by nothing that is run |

## Verified

All seven suites green on the pushed commit: unit 3,721, integration 789, contract 225, e2e 81,
agent 104, security 28, eval 68. Every model answer in the tests is **scripted**: whether a real
model makes the right calls (reading, check, end dates, clean-up verdicts) is **not measured**.

## The context, as agreed (built and on main)

Profile (identity + rules/preferences that apply, dated) -> Conversation summary (written by
the LLM, long chats only; none without a model) -> Learned skills (steps, track record, task
match) -> Tools (only known values, missing arguments, next step) -> Recent conversation (day
and time per message, tool steps with their age) -> Memories (related, each once, dated; most
related first, then time order) -> Documents -> Memory status (one sentence, when not
complete). On-demand agents (`recall: false`) get everything but Memories and Documents and
fetch the rest with the memory tools. No Facts lines (a search asks for facts by kind), no
People section, nothing said twice. Do not redesign; change only when a measurement says so.
